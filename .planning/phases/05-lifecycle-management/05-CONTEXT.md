**Gathered:** 2026-03-31

## Decisions

### 1. 端口分配策略
**决策:** 混合模式（C）

- 优先使用用户指定的端口（`--port 2000`）
- 如果未指定或端口被占用，自动分配可用端口（2000-2100范围）
- 端口冲突时提示用户并提供替代方案

### 2. 状态持久化位置
**决策:** 用户 home 目录（B）

- 路径: `~/.ensp/running_devices.json`
- 全局状态，跨项目/目录可见
- 支持多个终端窗口同时查看运行中的设备

### 3. GUI 兼容性（关键决策）
**决策:** 集成模式（C）+ 拓扑文件同步

**核心机制:**
1. **检测 GUI 设备**: 扫描 `eNSP_Router.exe` / `eNSP_Switch.exe` 进程
2. **端口协调**: CLI 启动设备时避开 GUI 已占用的端口
3. **拓扑文件修改**: 将 CLI 启动的设备写入 `.topo` 文件
   - 添加 `console_port` 属性到设备节点
   - 添加 **坐标位置** `cx`, `cy`（避免与现有设备重叠）
   - 标记为 `source="cli"` 区分来源
4. **GUI 重新打开**: 
   - eNSP GUI 重新打开拓扑时能识别这些设备
   - 设备显示在正确位置（基于 cx, cy）
   - 支持 GUI 接管（如果需要）

**技术实现:**
```xml
<!-- 在 .topo 文件中的设备节点 -->
<dev id="10" name="R3" model="AR2220_Router" 
     cx="500" cy="300" 
     com_port="2005" 
     source="cli"/>
```

**坐标分配策略:**
- 自动计算现有设备的边界框
- 新设备放置在右侧或下方（网格布局）
- 默认间距: 100 像素
- 或允许用户指定 `--x` 和 `--y` 参数

### 4. 启动失败处理策略
**决策:** 自动重试（A）

- 最多重试 3 次
- 每次重试间隔 2 秒
- 重试原因记录到日志
- 3次失败后报错并清理资源

### 5. 同时运行设备数量限制
**决策:** 可配置限制（C）

- 默认限制: 10 个设备（防止资源耗尽）
- 可通过 `--max-devices` 或配置文件修改
- 达到限制时提示用户停止现有设备

### 6. 设备名称冲突处理
**决策:** 禁止重复（A）

- 全局命名空间（通过状态文件统一管理）
- 尝试启动同名设备时报错：
  ```
  Error: Device 'R1' already running (PID: 12345)
  Use 'ensp-cli stop-device R1' first, or choose a different name.
  ```
